# Python SDK dependencies

This file registers third-party Python dependencies for the PACT protocol's Python SDK. The candidates come from the primitive probes in [probes/py.md](probes/py.md): a dependency is considered only where the standard library failed its probe, plus the development tools. A dependency reaches the Python manifest only after a vet with `rsx` in deep mode (`rsx analyze <repo> --mode deep`) passes the balanced policy check (`rsx policy test <repo> --policy-profile balanced --mode deep`). A failure is recorded here instead of a pin. Each row captures what `rsx` reported plus separately verified facts: license and release date from PyPI package metadata (`https://pypi.org/pypi/<name>/json`) and the `LICENSE` file at the release tag of the upstream repository, known vulnerabilities for the exact pinned version from the OSV database (`api.osv.dev`, queried 2026-10-16). Anything not verified is marked "to verify". The manifest and lockfile themselves are written by the scaffold work, not here; the versions below are the versions to pin.

- **Dependency** – the PyPI distribution name, with the GitHub repository `rsx` analyzed
- **Used by** – the part of the SDK that imports it
- **Version to pin** – the exact version to put in the lockfile, with the Python versions it declares (`Requires-Python`)
- **License** – the SPDX license expression
- **Maintenance** – `rsx` maintenance signals and separately verified facts, including the date the pinned version was uploaded to PyPI
- **rsx verdict** – the `rsx` result under the balanced policy, with the date of the vet
- **Constraint** – where the dependency may or may not be imported, or a platform or Python-version limit; `none` when there is no constraint

## Vetted dependencies

All 15 repositories analyzed (13 in the tables below, plus the two `pyright` candidates under "Rejected and not adopted") passed `rsx analyze --mode deep` and `rsx policy test --policy-profile balanced --mode deep` on 2026-10-16; both commands exited 0 for each. No policy failure blocked a pin.

`rsx` limits that apply to several rows:

- `rsx` reports the license of several repositories as `NOASSERTION` (unknown, license score 3.0/10). For those rows the license shown was verified from PyPI metadata and the repository `LICENSE` file, and the `rsx` license signal does not apply.
- The deep-mode OpenSSF Scorecard step timed out (30 s limit) on two consecutive runs for `pyca/cryptography`, `astral-sh/ruff`, `microsoft/pyright` and `RobertCraigie/pyright-python`. Their `rsx` security scores therefore lack Scorecard input and are not comparable with the other rows. Where the public OpenSSF Scorecard API (`api.securityscorecards.dev`) had a current result, it is cited as supplementary.
- `rsx` does not itemize its Scorecard "Vulnerabilities" check. For the two rows where it scored 0/10 (`jsonschema-specifications`, `pytest`) the findings were itemized with the OpenSSF `scorecard` command line tool (2026-10-16); the advisories sampled against OSV name other packages, not the vetted one. Other low scores are marked "not itemized". The OSV result for the pinned version is stated in each row.
