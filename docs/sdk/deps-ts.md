# TypeScript dependencies

This file registers third-party npm dependencies of the PACT protocol's TypeScript SDK (`ts/`). A dependency reaches `ts/package.json` only after a vet with `rsx` in deep mode (`rsx analyze <repo> --mode deep`) passes the balanced policy check (`rsx policy test <repo> --policy-profile balanced`). A failure is recorded here instead of a pin. Each row captures what `rsx` reported plus separately verified facts: every license and release date below was read from the npm registry metadata or from the repository `LICENSE` at the tag, not from `rsx` alone, and anything not verified is marked "to verify". The dependency itself is added to `ts/package.json` in the work that scaffolds the package, not here. Rows are appended as dependencies are vetted; existing rows are only edited to correct them or record a re-vet.

Most primitives need no package: ES256 sign and verify, JWK import and export, the RFC 7638 thumbprint, base64url, UTF-8 decoding, strict JSON parsing, RFC 8785 canonicalization and the test runner come from Node builtins or in-house code, per the decision table in [`probes/ts.md`](probes/ts.md). Only the packages below are needed.

- **Dependency** – the npm package, with the GitHub repository `rsx` analyzed (slug confirmed from the `repository` field of the registry metadata)
- **Used by** – runtime or dev dependency, and what it is for
- **Version to pin** – the exact version to put in `ts/package.json` (npm `latest` on the vet date), with its declared Node `engines` constraint
- **License** – the SPDX license identifier
- **Maintenance** – `rsx` maintenance signals and separately verified facts, including the date of the latest release
- **rsx verdict** – the `rsx` result under the balanced policy, with the date of the vet
- **Constraint** – how the dependency may be used; `none` when there is no constraint
