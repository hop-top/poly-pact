## 3. Strict parse: a port of the Go walker

`strictjson` is a pure-Python port of the Go walker (`go/core/strictjson/walk.go`) and of the `encoding/json` token rules it runs on (`Decoder.Token`, `More`, `InputOffset`): one pass over the text, in step with the target type, that reports the first violation with the reason, RFC 6901 path and byte offset the Go package reports (owner decision of 2026-10-19).

1. **Before the walk**: the size limit, then a strict UTF-8 decode; `UnicodeDecodeError.start` is the offset Go's `utf8.DecodeRune` loop reports. A BOM is not white space, so it is a syntax error at offset 0.
2. **The walk** reads tokens with the decoder's token states (top value; array start, value, comma; object start, key, colon, value, comma), so a syntax error lands where Go reports it, and a failed token whose text starts with `NaN`, `Infinity`, `-Infinity` or `+Infinity` is `NON_FINITE`. Open containers sit on an explicit stack: the depth check does not depend on the interpreter's recursion limit, and the walk stops at the first container past the limit without reading the rest (Go's `TestDepthIsCheckedBeforeBodyIsRead`). Per member: duplicate name (compared after unescaping), then unknown field (exact, case-sensitive). Per number: an integer literal of more than 16 digits is refused before `int()` (a 5000-digit literal otherwise raises `ValueError` from the digit limit), then the `±(2^53-1)` range, then the integer-field rules (negative, fraction or exponent); `float()` gives the non-finite check. Per null: the target must be nullable.
3. **After the walk**, in Go's order: the first unpaired surrogate escape (noted while strings are decoded, reported only when the walk found nothing else, since Go checks surrogates after the walk), then the first value that does not fit its target type (`TYPE`, empty path, offset the end of the top-level value, as `encoding/json` reports it).

Targets are read from the dataclass annotations with `typing.get_type_hints`: `str` (and `StrEnum`), `int`, `float`, `bool`, a dataclass, `tuple[X, ...]`, `Mapping[str, X]`, `X | None` (nullable, Go's pointer), and `JSONValue` or any other union for a free-form value (Go's `json.RawMessage`). A wire type of `core.types` takes nullability from its `_MEMBERS` table, so an optional member such as `extensions` (`JSONObject | None = None`) is absent-or-object, not nullable. An absent required member holds its Go zero value; required members are the schema validator's, as in Go. Values: objects `dict`, arrays `tuple`, integer literals `int`, other numbers `float`.

`tests/testdata/strictjson-go-verdicts.json` records the kind, path and offset that the Go package reports for 142 inputs (every `TestDecodeRejects` case, the syntax and offset edges, typed and untyped targets); the port reproduces all of them.

Throughput on the 256 KiB document of the probe record (Q7), decoded as a `RequirementContract`, best of 25 runs, measured 2026-10-19: 33 ms on 3.11.16 and 46 ms on 3.14.8 (`json.loads` without hooks: 1.2 ms and 1.7 ms). The token-state emulation costs about 4 ms on 3.11.16 and 13 ms on 3.14.8 over the probe's walker (29 ms and 33 ms).

Rejected alternative: two passes. Pass 1 was `json.loads` with hooks raising a private reject (`object_pairs_hook` for duplicate keys, `parse_int` with the length check, `parse_float` and `parse_constant` for non-finite values, `JSONDecodeError` to `syntax` or `trailing-data`, `RecursionError` to `depth`), after a surrogate-escape scan; pass 2 a typed walk over the tree with RFC 6901 paths and offset 0. It was faster (probe record, Q7: 6 ms against 29 ms on 3.11.16, 9 ms against 33 ms on 3.14.8), but two Go tests do not pass under it: `TestErrorFields` requires a positive offset for an unknown member, a pass-2 finding, on every interpreter; and `RecursionError` is first raised at a nesting that depends on the interpreter and the caller's stack (Q13: 991 to 994 on 3.11.16, about 10 000 on 3.12 and 3.13, about 116 000 on 3.14.8), so on 3.14 the 100 000 unclosed `[` of `TestDepthIsCheckedBeforeBodyIsRead` end in `JSONDecodeError` (`syntax`) instead of `depth`. A document with violations found in different passes could also name a different first violation than Go.

Floats match Go after the non-finite check: Go's `ParseFloat` returns 0 without error for `1e-400` and errors for `1e400`; Python's `float()` gives `0.0` and `inf`. `-0.0` parses to negative zero in both and JCS writes `0`. The unit tests add `1e-400` and `2.5e-324` (which becomes `5e-324`).

## 4. Idioms

- **Errors.** `PactError(Exception)` root; one subclass per Go family with a `kind`, `reason` or `code` attribute holding the Go strings; `code_of`, `reason_of`, `kind_of` walk `__cause__` and `__context__` through `PactError` instances only.
- **Instants.** Aware `datetime`, which ends in year 9999; `clock.replay_retention` returns `datetime.max` with `tzinfo=UTC` (no expiry) for a retention past it, never an earlier instant and never an exception.
- **Bytes.** `bytes` on the public surface; `str` for compact JWS and identifiers. Base64url decoding runs four checks first (alphabet only, `len % 4 != 1`, no `=`, spare bits zero), then pads and calls `b64decode(..., altchars=b"-_", validate=True)`. `urlsafe_b64decode`, `b64decode(validate=True)` and `a2b_base64(strict_mode=True)` all accept `AB==` (non-zero spare bits; unpadded `AB` fails their padding check), and `urlsafe_b64decode` skips newlines (probed 2026-10-16, re-probed 2026-10-19).
- **Output.** JCS writer, or `json.dumps(separators=(',', ':'), ensure_ascii=False)` over dataclasses in schema member order. Go's `TestRoundTripByteStable` ports with `json.dumps(indent=2, ensure_ascii=False)` and stays the tripwire for the parsed-value model.
- **Crypto.** `cryptography` for ECDSA and key import and export; `hashlib.sha256`; `hmac.compare_digest`. Deterministic signing is available in the pinned version but not used, to match Go's randomized signing.
- **Typing.** `mypy --strict`; `py.typed`; `Protocol` for every Go interface; `Final` for constants.
- **Schema module.** `jsonschema` 2020-12 through an offline `referencing` registry. Unknown formats are ignored unless a `FormatChecker` carries them, so the module registers exactly one checker, `uri`, backed by the in-house matcher.

## 5. Dependencies, pins and guard

Runtime: `cryptography` 50.0.2, `jsonschema` 4.26.0, `referencing` 0.37.0, with their vetted transitive sets. Development: `pytest` 9.1.1, `ruff` 0.17.1, `mypy` 2.4.0, `rfc8785` 0.1.4 (test oracle only). Build: `build` and one backend, both to vet: `flit-core` (no dependencies; supports the src layout, package data and `py.typed`, confirmed 2026-10-19 in the probe record, Q8) is the choice; if it fails the vet, `hatchling` with `packaging`, `pathspec`, `pluggy` and `trove-classifiers`. No `rfc3986-validator`, no Hypothesis, no pytest plugins. The adapter stack, manifest, binding and case loader are standard library.

Pins: ranges in `pyproject.toml` (for example `cryptography>=50.0.2,<51`); exact pins in `py/constraints.txt`, without hashes: pip 26.2.1 refuses hashed constraints next to an editable install ("there is no single file to hash"; probe record, Q11). `mise run install` and the publish test command use `pip install -c constraints.txt -e ".[dev]"`. The package audit of the dependency vet runs over `constraints.txt`. A test asserts every constraint satisfies its `pyproject.toml` range.

`tests/test_depcheck.py` parses `pyproject.toml` with `tomllib` and asserts: runtime dependencies equal the vetted set; `[build-system].requires` is within the vetted build set; imports under `src/` (walked with `ast`) are the standard library, the package, `cryptography`, `jsonschema` or `referencing`; `tests/` may add `pytest` and `rfc8785`; `examples/` uses the runtime set only; `attrs`, `rpds` and `referencing` internals are never imported directly. It has a negative control on a copy.

## 6. Conformance strategy

1. **Vectors harness** per the shared plan (section 5); `PACT_REQUIRE_VECTORS=1` in `make py-test` and CI.
2. **Unit tests** ported one-to-one, including the 10 000 `numbers.json` rows, the round-trip test and the float edges of section 3.
3. **Draft-reading tests**: section 7.3 typ table, section 20.1 limits and lifetimes, freshness profile vocabulary.
4. **Schema drift**: generated dataclasses and `_MEMBERS` against the vendored schema; vendored schema against `spec/v1.0/schemas` by `make py-check-schema`.
5. **Property test** for JCS over random trees with a fixed seed, drawing doubles from random 64-bit patterns (`struct.unpack`) so subnormals and large exponents occur; a long seeded run under `make py-fuzz` nightly, the counterpart of Go's nightly fuzz.
6. **Adapter suite**: 88 common cases against the memory adapter and the broken catalogue, plus the case-file rule, registered-in-manifest and draft-heading tests.
7. **Mutation patches** (shared plan, section 5.6), listed per task in section 9.
